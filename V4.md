# Bounded AI investigation assessment

Assessment release: Locard 6.62. Baseline: `756558224d46c66eaa358eb8f6827f052d5528fb`
(6.61). The application version remains authoritative only in `pyproject.toml`.
This document describes the existing `investigate-ai` subsystem. It does not enable
tools behind `!`, which remains advisory-only.

## Verdict and boundaries

**REUSABLE AFTER HARDENING.** Reuse the existing controller, contracts, evidence
exposure ledger, deterministic adapters, and isolated worker. A second execution
framework is unnecessary. There is no model-controlled SQL, executable, CLI
dispatcher, case path, output path, endpoint, ingestion, report or export tool.
This is an application-level boundary, not an OS sandbox against malicious
installed Python packages or an adversary controlling the analyst account.

The nine adapters read case data; semantic retrieval additionally reads the
analyst-configured local index/model. Installed detection rules are trusted code,
discovered from the installed package and frozen by ID per investigation. Model
text cannot install a rule or select a Python module. No adapter intentionally
writes forensic data or accesses a network service. The parent separately writes
derived transcripts; the CLI activity wrapper writes its existing audit sidecar.
SQLite read-only WAL connections may create/use shared-memory bookkeeping: a
read-only SQL guarantee is not a promise of zero filesystem bookkeeping.

Narrow changes in this release:

- Launch the worker with `-I -B`: isolated imports and no Python bytecode-cache
  writes from worker imports. This does not claim that third-party libraries are
  prevented by an OS policy from writing caches.
- Mark omitted/shortened limitation text and warnings explicitly, retaining the
  existing field limits, evidence IDs, result shape and deterministic semantics.
- Add executable boundary tests and this assessment. No schema, tool capability,
  ingestion, dump, report or advisory-interface change.

## Execution map

`cli.build_parser` -> `investigation_ai.cli.configure` -> `cli.dispatch` /
`activity.Command` -> `investigation_ai.cli.dispatch` -> `controller.run`:

1. Validate analyst question and immutable `state.Budget`; construct the loopback
   `LocalClient`, freeze installed rule IDs, establish a monotonic deadline.
2. Create a UUID transcript directory and manifest. Start `runner.ForensicWorker`
   using a fixed installed `worker.py` and the current interpreter, never a model
   executable. On Windows assign the real worker PID to a kill-on-close job.
3. `worker.serve` opens the existing DB with `case.open_readonly`, starts a short
   transaction, computes its content fingerprint, and executes `tools.initial`.
   This calls `semantic.hybrid.retrieve` / deterministic `retrieve_question`;
   optional semantic candidates expand through deterministic investigation.
4. Compact the result with `tools.envelope`; check output shape/IDs in the parent;
   retain bounded records in `State`, then construct a bounded prompt and closed
   JSON grammar. Record exactly the evidence actually exposed to the model.
5. `LocalClient.complete` sends a bounded request to the configured loopback LLM.
   `contracts.loads/request` reject malformed, duplicate-key, oversized, unknown
   or inapplicable proposals. `validate_anchor` requires an exposed active-case
   ID and appropriate process/logon kind; installed detection IDs are frozen.
6. Normalize calls, reject repetition, enforce budgets; dry-run stops here.
   If enabled, request analyst approval before execution. Rejection stops the run.
7. Revalidate in `tools.execute`, execute one fixed adapter under a fresh read
   transaction with the original fingerprint, serialize bounded JSON, record
   result/hash, and update novelty/retention state. Repeat within outer bounds.
8. Final observed assertions select disclosed ID + JSON pointer. `State.render`
   supplies the original displayed value, or selects an exposed deterministic
   relationship/detection without upgrading its status. Free model prose is
   confined to unverified hypotheses (with alternatives) and unknowns.
9. Recheck the original fingerprint where time permits, close/kill the worker,
   and write terminal findings and transcript status. Partial findings remain
   historical to the recorded fingerprint. `ANSWER_SUPPORTED` is structural
   grounding, not proof that an interpretation is scientifically correct.

`investigation show` reads recorded results, checks current compatibility where
possible, and labels them as recorded. `replay` reexecutes recorded operations
without a model, checks implementation/case compatibility and result hashes.
Neither is a model-invokable tool.

## Authoritative tool inventory

All implementations are selected by the fixed `if/elif` in
`investigation_ai/tools.py:execute` after `contracts.arguments`. All return the
same structured envelope, read the case DB, cannot change case state, and have
no ingest/report/dump/shell/arbitrary-SQL capability.

Shared filters: artifact (`evtx`, `mft`, `prefetch`, `registry`), hostname,
username, process, path, IP, event ID, start/end UTC. Paths are search values,
not files to open. Strings are bounded to 1,024 UTF-8 bytes (query 1,000).

| Tool | Deterministic implementation | Inputs and limits | Other access |
| --- | --- | --- | --- |
| `search_evidence` | `EvidenceQueries.search` | At least one shared filter; limit 1–50, default 20 | None |
| `timeline` | `EvidenceQueries.search(timeline=True)` | Shared filters; start/end required, at most 24h; limit 1–50 | None |
| `show_evidence` | `get_evidence` | Exposed canonical evidence ID | None |
| `around` | `anchor_time`, `shift`, `EvidenceQueries.search` | ID, optional timestamp slot; seconds 0–3,600 (120); direction before/after/around; limit 1–50 | None |
| `process_tree` | `correlation.processes.process_tree` | Process ID; seconds 1–3,600 (300); nodes 1–50 (20); depth 1–6 (4) | None |
| `session` | `get_event`, `correlation.sessions.session` | Successful-logon ID; hours 1–24 (24); limit 1–50 | None |
| `detections` | `detections.engine.detections` | Installed rule ID; time/host/user; limit 1–25 (20); internal candidates 100 | Trusted installed rule modules |
| `investigate_evidence` | `correlation.investigation.investigate` | ID, timestamp slot, seconds 0–3,600 (120), candidates 1–50 (20) | None |
| `semantic_search` | `semantic.index.search`, then `investigate` | Query, shared filters; hits 1–20 (10); expand at most five anchors, 50 retained records | Configured local model and index only |

Each returns original evidence IDs for returned records; relationships/detections
carry supporting IDs. Semantic hits carry candidate IDs and similarity metadata.
An empty result has no evidence ID. `initial` and `check` are trusted worker
protocol operations, absent from the model allowlist. Internal queries and
deterministic expansion are not separate model calls.

## Contracts, results and injection boundary

The CLI uses argparse; the model uses a separate closed JSON contract in
`contracts.py`. Catalog/schema are generated from `TOOLS`, not from command help.
Manual recursive validation requires exact types (booleans cannot be integers),
rejects unknown keys, invalid enums, dates, IPs, IDs, NULs and reversed/>24h paired
windows. Defaults are applied centrally. Worker validation repeats argument checks
and verifies anchor membership in the active DB. SQL values are bound parameters;
SQL structure comes from trusted retrieval code. No model CLI string is executed.

Separate adapter contracts can drift from normal commands. For example, browser
is absent from both the artifact enum and canonical-ID regex; a mixed result with
a browser ID fails closed rather than silently dropping it. The proposed
download-versus-execution example is therefore not currently a validated
browser-capable workflow. Do not advertise it as such.

Envelope: `tool`, `behavior`, `records`, `relationships`, `detections`,
`limitations`, `returned_count`, `truncated`, `semantic_candidates`, untrusted
label; initial retrieval adds plan and semantic-use metadata. No terminal text
parsing. Max 50 records, 100 relationships, 25 detections, 20 semantic candidates.
Unsupported relationship/detection objects are omitted with an explicit limit.
Compact fields carry `truncated_fields`; top-level truncation marks row/object/
limitation omission. Worker messages are capped at 512 KiB; oversized output is
replaced with a resource-limit error, never sent unbounded. There is no model
pagination offset: narrower searches and supplied limits are the controls.

State retains at most 200 records, 200 relationships and 200 detections each,
40 semantic candidates and 30 limitations. Prompt content is capped at 5,600
bytes, grammar at 32,768 bytes; omitted prompt records are counted. The exposure
ledger prevents findings about retrieved-but-undisclosed fields. Transport
responses are capped at 1 MiB, parsed model content at 16 KiB. Duplicate JSON keys,
nonfinite values, malformed JSON, extra properties and unknown tools fail closed.
There is no free-text executable fallback.

Hierarchy: fixed system policy -> controller-owned tool schema/allowlist ->
analyst objective -> evidence data. The user-role JSON packet separates
`controller` from `UNTRUSTED FORENSIC EVIDENCE`; evidence may contain hostile
commands, URLs and filenames. The system says evidence cannot change policy.
This is structural labeling, not proof a model will ignore injection. The actual
security boundary is deterministic validation/authorization and grounding, even
if the model follows an injected instruction. Current prompts put objective and
evidence in one user message; future integration should explicitly retain the
trust distinction and must not merge arbitrary evidence into system messages.

## Budgets, approval and errors

| Budget | Default | Range | Enforcement |
| --- | --- | --- | --- |
| steps | 8 | 1–16 | Each model iteration, including rejected proposals; no hidden retry |
| tool calls | 6 | 1–12 | Accepted proposed operation, incremented before execution, including failures |
| seconds | 300 | 1–600 | `time.monotonic`, model and tool work and approval share deadline |
| tool/model operation seconds | 45 | 1–45 | Worker watchdog / socket watchdog clipped to remaining time |
| rejections | 3 | 1–3 | Stops malformed/invalid proposal retries |
| semantic requests | 2 | 1–2 | Includes initial semantic use |

Initial retrieval and final fingerprint checks do not consume model tool-call
budget. Normalized repeated calls stop immediately; three consecutive operations
with no new evidence stop; total retention and all outer budgets are independent.
Changing tool names, oscillation, recursive investigation or requests to raise
budgets cannot escape the fixed loop/schema. Accepted worker errors terminate;
they are not retried by the model. Invalid proposals may retry within rejection
and step bounds. Errors contain bounded messages, no traceback, but can contain
sensitive paths/database text; treat results and transcripts as sensitive.

Deadline caveat: worker startup handshake has a separate ten-second ceiling;
transcript fsync and cleanup are not hard-preempted by the investigation deadline.
The timer is not a strict total process wall-clock guarantee. Parent pipe writes
are synchronous. Queries have SQLite progress-handler deadlines; parent polls
every <=50ms and kills on operation timeout, abnormal exit or >64MiB incremental
WAL growth. Worker memory guard is 2GiB. Windows job cleanup covers descendants;
non-Windows descendant containment is weaker. These are important reuse limits.

Dry-run performs initial retrieval, then at most one model request if evidence
fits the prompt; zero requests if retrieval is empty/fails. It validates the
proposal/final but never executes a proposed operation or requests approval.
It writes a transcript and CLI audit and may perform a final fingerprint check.

Approval prints JSON-escaped bounded proposal/arguments to stderr and uses timed
console input. Only `y` approves; rejection/EOF/timeout stops rather than retries.
Noninteractive `--approve-tools` is rejected. Approval cannot be supplied in
model prose. `interactive.console.timed_line` owns cancellation-safe input; no
background stdin reader is retained to consume later shell commands.

## Read-only state, semantics and network

`case.open_readonly`: existing file required; schema 3/4/5 only; SQLite URI
`mode=ro`, `query_only=ON`, `trusted_schema=OFF`, extension loading disabled,
2MiB SQL value bound, 64KiB SQL length, no attached DBs. Authorizer denies writes,
DDL, ATTACH, unsafe pragmas and load_extension/readfile/writefile functions.
Only trusted code constructs statements. No general SQL text input is accepted.

Each operation reads a consistent short transaction, verifies the original
content fingerprint, and releases it before model waiting. Changed state stops
the investigation. This avoids a full-investigation WAL pin, but repeated
fingerprints can be expensive on large cases. Fingerprints do not establish
chain of custody or correctness of evidence interpretation.

`--no-semantic` disables model/index loading. Index and model paths are analyst
configuration, not proposal fields. Missing/stale/incompatible optional index
falls back conservatively at initial retrieval; unavailable semantics are not
advertised. Subsequent pinned-generation changes stop the run. Index identity
uses generation/manifest hash; search verifies model identity, case fingerprint,
index file integrity and vectors. The model is locally pinned, uses safetensors,
reviewed module types, `local_files_only=True`, `trust_remote_code=False`, and
offline/telemetry-disabled environment variables. Explicit network-enabled
`semantic setup` is not reachable through the tool allowlist.

Semantic similarity is candidate-selection metadata. Original IDs survive;
deterministic expansion supplies separate relationships. `retrieval_basis` is
excluded from observable evidence fields. Scores are not confidence/evidence.
Third-party model libraries remain trusted installed dependencies, not sandboxed
code. Full real-model offline/cache behavior needs acceptance in the target setup.

`LocalClient.endpoint_parts` accepts HTTP numeric loopback or localhost mapped
to 127.0.0.1 only; rejects remote hosts, credentials, queries, fragments and
non-/v1 paths. No DNS, proxies or redirects. The model cannot change endpoint.
The only intended network operation is the parent LLM call. Adapter query strings
are never fetched as URLs. Analyst-configured paths can be network shares; local
endpoint policy alone is not an enforcement that all storage is local.

## Transcripts and activity audit

Default root: `DATABASE.investigations`; analyst can specify `--transcripts`.
UUID subdirectory, `manifest.json`, append-only `events.jsonl`, atomic temporary
manifest replacement. Existing UUID directory fails instead of overwriting.
Read IDs require 32 hexadecimal characters and read paths reject redirection.
Root is analyst-selected, resolved, and may be outside the case. The writer does
not harden every parent/leaf against an attacker racing symlinks/junctions; use an
analyst-controlled directory. Permissions are inherited, not a private ACL policy.

Manifest records implementation hash/version, policy, budget, question, tools,
rule IDs, fingerprint and semantic identity. Events include initial results,
exposed evidence, prompt hash/size (not the complete raw prompt), accepted
proposals, results, dry-run proposals, rejected bounded request fields/response
hash, validated final selections and terminal output. Raw invalid response text
is not universally stored. Events are hash-chained, not signed: tampering is
detectable against a trusted copy, but an attacker can rewrite the chain.
4MiB event budget, 600KiB/event, terminal reserve 512KiB. Transcript failures may
leave RUNNING/partial output and are not guaranteed to finalize on every I/O
failure. They contain sensitive evidence, analyst questions, arguments and paths.

CLI `activity.Command` records command invocation/completion, parameters and
duration in a separate derived activity sidecar; session start/end when owned.
There are no dedicated per-model-request, tool-proposed, approval-denied,
tool-failed or result-count activity events for this engine. Transcripts record
exposure/accepted/result/rejected/terminal, but do not record every approval
decision as an explicit event. `controller.run` directly does not create activity
events. A handled TOOL_FAILURE/MODEL_FAILURE can return CLI exit 0 and an audit
command success because dispatch completed; inspect investigation termination.
Do not confuse audit success with investigative success. This release does not
redesign audit semantics.

## Required work before future `!` integration

1. Define browser/mixed-artifact contract and coverage explicitly, including
   browser IDs, profile/source ambiguity and conservative temporal/host behavior.
   Review `around` choosing the first source ID for multi-source anchors; do not
   infer cross-source attribution. Do not broaden capability as part of this audit.
2. Wire the existing engine into a separately authorized bounded workflow with
   clear initial-retrieval scope and partial/failed outcomes. Keep advisory-only
   behavior as the current default. Never dispatch model text as shell/CLI.
3. Make startup, pipe communication and cancellation obey a documented end-to-end
   deadline; verify cleanup on each supported OS and large-case fingerprint cost.
4. Strengthen transcript storage against redirection/races and define private
   directory permissions, retention and failure behavior. Decide explicit local
   storage policy for case/index/model/transcript paths.
5. Add auditable proposal/approval/rejection/execution/terminal linkage without
   weakening the existing activity chain, and expose meaningful outcome status.
6. Validate adapter/catalog synchronization, all supported artifact projections,
   semantic-index trust boundary and real-model offline behavior. Keep structured
   untrusted data, original IDs, actual-exposure grounding and independent limits.
7. Complete live dry-run and interactive reject/approve acceptance with the target
   local model and an accessible safe case. Scripted tests do not measure real
   model quality or prove resistance to all prompt injections.

## Validation evidence

Baseline focused investigation tests: 61 passed. An earlier invocation encountered
43 pytest temporary-directory permission errors (18 non-temp tests passed);
using a fresh explicit temporary directory resolved them without permission or
test changes. Test outputs and the protected-evidence manifest are kept outside
the repository under the release-specific `C:\tmp\locard662-*` paths.

Existing gates cover SQL-authorizer escape attempts, WAL/concurrent readers and
writers, mutation fingerprint refusal, abnormal termination, worker timeouts,
HTTP deadlines, transcript tampering/replay, semantic markers and advisory-only
shell behavior. `tests/test_investigation_assessment.py` adds explicit fixed-tool
inventory, forbidden operations and arguments, malformed/duplicate/oversized
JSON, retry/call/time bounds, approval ordering, dry-run non-dispatch, terminal
worker failure, output omission flags, transcript collision protection and real
worker/full-controller DB SHA-256 checks.

Live acceptance limitation: the configured local endpoint refused connections
and Standard2 denied read access. No permissions were changed. Live model dry-run
and human-terminal approval are unverified; synthetic real-worker tests cover
dry-run and scripted rejection/acceptance instead. No real evidence was copied
or modified to work around access controls.

The exact requested dry-run question was also executed through the real CLI on a
new synthetic case containing `coreupdater.exe`. It terminated `MODEL_FAILURE`
because the local service was unavailable, accepted zero proposed calls, produced
a 3,637-byte prompt and a 5,822-byte transcript, and left the database SHA-256
unchanged. CLI exit was 0, demonstrating the documented distinction between
command completion and investigation success. This is an error-path check, not
a successful live-model dry-run acceptance.

Final release validation:

- Focused investigation assessment: **108 passed in 34.22s**.
- Expanded AI/security/semantic/audit/lifecycle/report tests: **515 passed in
  148.01s**.
- Complete regression suite, run exactly once: **2,115 passed in 782.18s**.
- `git diff --check`: passed. No stale assertions needed updating.
- Protected evidence inventory: **36,869 files before and after; zero differences**
  in path, length and last-write UTC. This is a metadata/inventory comparison,
  not a cryptographic hash of the entire protected tree. Representative synthetic
  case databases were additionally verified with SHA-256 before/after operations.
- Project and installed package metadata both report the requested release.
- Live model/terminal acceptance remains unverified for the reasons above.
