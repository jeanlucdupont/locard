# Locard 6.137 — Findings workspace identity binding

## Defect and scope

Starting revision: `d5d9d97389efcac16ddaec3ea69af2221534816e`, application 6.136. Source version is now 6.137 in `pyproject.toml`. The pre-existing modification to `docs/PYTHON_FILE_MAP.md` is preserved and is not part of this correctness change.

Previously `Workspace(directory)` retained only a path. `_write()` validated structure, the event chain, expected revision, current source binding and transitions, but compared workspace UUID only when `expected_workspace_id` was supplied. `register()`, `review()`, `supersede()` and single-result imports supplied no UUID. A different valid same-source workspace at the same revision could therefore receive a stale handle's write.

The existing UUID is `metadata.id`, generated by `uuid.uuid4().hex`. Event bodies already contain `workspace_id`; genesis and event hashes are unchanged. No schema or migration is needed.

## Existing AI-capture protection

`finding_capture.Capture.__init__()` opens the workspace and `_inspect()` captures its UUID while verifying the prepared request/source/read-view binding. `finish()` inspects again, asks the separate save confirmation, then calls `import_results(..., expected_workspace_id=self.workspace_id, expected_revision=state['revision'])`. The explicit UUID was checked inside `_write()`.

This mechanism is preserved. The common write path now always checks a prior selection, so capture's explicit UUID is an additional consistency assertion, not the only protected entry point. Provider authorization and saving remain separate decisions.

## Selection and API contract

`Workspace(directory)` now immediately opens the existing database read-only, validates its schema, metadata and complete event chain, and pins a deep copy of:

- Workspace UUID.
- Original recorded source/read-view binding.
- Recorded source-root path.

Opening does not require the transcript to remain available: public export retains its existing unavailable/invalid-source status behavior. Every write still requires successful current source reconstruction and candidate validation.

`create()` initializes the path privately, creates the existing schema exclusively, commits the existing genesis metadata, and pins the UUID/binding it generated. It does **not** reread a potentially substituted pathname to choose the identity returned to the caller.

Public mutation signatures and CLI syntax are unchanged. The caller still supplies `expected_revision`; the opened handle supplies the independently pinned UUID. The optional explicit UUID on batch capture must agree with that pin. A missing/invalid pin fails closed, even if an explicit UUID was passed to the internal writer. There is no path-only fallback.

A stale handle never reopens and adopts replacement metadata. Public `export()`, `list()`, `get()` and `decisions()` reject substitution too. An explicit new `Workspace(path)` selects the currently present valid workspace; it is not an automatic retry. Moving a selected workspace requires explicitly opening its new location. Revision is not frozen in the handle: callers may continue against the same UUID using a newly obtained expected revision.

Compatibility boundary: construction of a missing, malformed or unsafe workspace now fails immediately rather than waiting for the first operation. Python callers that previously created a lazy handle before the database existed must use `create()` or open an existing valid workspace. No manual UUID entry is required.

## Transaction invariant

All mutation paths converge on `_write()`:

```text
register / review / supersede / import_d2 / import_result / import_results
  → guarded SQLite mode=rw connection
  → BEGIN IMMEDIATE
  → load metadata, validate event chain, reconstruct current state
  → compare actual UUID with pinned UUID and any explicit UUID
  → compare original source binding and source root with pinned selection
  → compare actual revision with caller's expected revision
  → reconstruct/validate source and existing candidates
  → build proposed event(s), validate transition through existing reducer
  → source consistency check
  → append event(s), COMMIT
```

Identity and revision checks occur inside the append transaction. An error rolls back. The build callback is not entered on an identity/revision mismatch. Existing source checks, byte/event bounds, duplicate capture checks, concurrency and review semantics remain.

| Diagnostic | Meaning |
|---|---|
| `FINDINGS_EXPECTED_WORKSPACE_ID` | Missing/invalid pinned identity or malformed explicit expectation. |
| `FINDINGS_WORKSPACE_CHANGED` | Actual, pinned or explicitly expected UUIDs disagree. |
| `FINDINGS_WORKSPACE_BINDING_CHANGED` | UUID matches but the selected source binding/root changed. |
| `FINDINGS_STALE_REVISION` | Correct workspace, wrong expected revision. |

Existing capture translates failed identity checks to its bounded failed/not-committed result; no retry is introduced. Existing source, integrity and invalid-transition diagnostics are retained.

## Future service contract and remaining debt

A future web service must map a server-owned workspace resource identity to its approved local path. A request carries/references the selected UUID, expected revision, operation and arguments. The server must compare that selection with its pinned handle before invoking mutation; it must not accept an arbitrary client filesystem path or use a fresh path lookup as proof of the client's prior selection. Keep the pinned handle through validation and mutation. If selection changes, require explicit reselection, never retry automatically.

This change does not add HTTP endpoints, sessions, a resource registry, typed errors, history caching or a task manager. Python private attributes are not a security boundary against malicious in-process application code. Hash chains establish consistency, not authentication; an exact copied store retaining UUID and binding is the same logical workspace for this contract. File ancestry, link checks and SQLite locking retain their existing responsibilities. Comprehensive typed errors and public resource handles remain future work.
