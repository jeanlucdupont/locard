# Locard 6.147 — CLI presentation refinement

## Scope and implementation

Inspected baseline: `bcf7d2f` (`main`, 6.146); the implementation described here is the uncommitted working tree. `pyproject.toml` declares 6.147 and remains the application version authority.

This release changes human presentation and contextual help. It does not change evidence queries, normalization, findings decisions, report digests, provider routing, authorization or persisted audit contracts.

| Problem | Correction / source |
|---|---|
| Verbose, inconsistent help | Canonical argparse descriptions edited at their registration sites; `cli_parser.classify_help` and `semantic_help` retain the shared parser |
| Generic footer and redundant choice lists | Removed generic epilog and default catalog footer; nested commands remain discoverable |
| Fixed-width/help alignment | Terminal-width layout, aligned continuation lines and usage wrapping; unusually long identifiers remain intact |
| Startup configuration confused with readiness | `ai.readiness.present` uses compact `ai.cli.render(startup=True)`; no connection probe |
| Status output too detailed | Human `ai status` adds connection and compatibility indicators; structured results unchanged |
| Case counts/limitations inconsistent | `retrieval.status_display.render` uses semantic fields and accurate empty/populated-case caveats |
| Audit internals overwhelm summary | `session_recording.integrity_summary`; CLI selects this only for human audit verification |
| Entire parser error colored red | Explicit `TextSpan` error/usage/recovery segments supplied by `InteractiveParser` |
| Question-mark help inconsistent | Shell resolves leading/trailing `?` through canonical subparser metadata, without dispatch |

## Editorial standard and inventory

Use short, action-oriented descriptions. State the operation first. Do not repeat command names, describe implementation unnecessarily or add generic “use help” footers. Preserve constraints that affect the analyst's decision: destructive effects, cloud disclosure, authorization, bounded/incomplete coverage, forensic uncertainty and overwrite behavior.

Examples:

| Entry | Revised description |
|---|---|
| `!` | Ask AI |
| `case list` | List available cases |
| `case open` | Open a case |
| `--page` | View output page by page |
| `--output` | Save output to a file |
| `--force` | Overwrite an existing output file |
| `--append` | Append output to a file |

The complete before/after text, lengths and advisory safety categories are in [the editorial inventory](LOCARD_6_147_HELP_INVENTORY.md). It was generated by `scripts/help_inventory.py` from canonical interactive parser metadata, using a captured baseline rather than reconstructed old wording. Structural subparser placeholders intentionally have no duplicate help. The tool flags empty and over-30-word descriptions for review; it never rejects helpful safety text or changes runtime behavior.

Three longer command descriptions are intentional review exceptions: advanced timeline analysis, advanced local-query analysis and evidence export. Inspect their full inventory rows before further shortening. Operation-specific authorization, disclosure, resource limits, analyst-supplied metadata and uncertainty guidance is retained. Keyword-based inventory categories are editorial triage, not security enforcement.

Simple commands use `Options`; commands with more than eight visible optional actions use common/advanced grouping where appropriate. No generic advanced-options introduction is printed. See [the regenerated command reference](LOCARD_SHELL_COMMAND_REFERENCE.md).

## AI and case status

Startup shows the `AI Provider` heading and Provider, Model and Status. “Configured” means configuration is present and passes existing configuration checks; it does **not** assert connectivity, credentials accepted remotely, model availability or Locard structured-output compatibility. Local configuration checks inspect existing configuration/files only. No local runtime or remote readiness request is started by this presentation.

Detailed `ai status` also shows Connection, Model compatibility and Locard compatibility. Unknown/unperformed checks are `not checked`. Configuration states map explicitly to semantic roles; JSON is unchanged. Existing explicit readiness/configuration operations keep their behavior.

Case status labels/headings use the existing heading/text roles; neutral counts and values use cyan `value`. Zero failures are not painted as operational success. Forensic qualifications use `forensic_note` (brown). Empty cases explain that no evidence has been ingested and activity cannot be assessed. Populated cases explain that absence of matching evidence records does not establish absence of activity and available data may be incomplete. Specific parser/source limitations are preserved; the generic stored caution remains unchanged in JSON.

## Audit and errors

Human `audit verify` shows activity-chain integrity, completed/verified sessions, this-process active sessions, unknown incomplete sessions and integrity-failure counts. A session is described as active only when the live recorder is not broken and its segment and head hash match the verified row. Other incomplete sessions remain unknown: they may be interrupted or active elsewhere. Missing/corrupt/unverifiable results are not converted into success. Full detail remains in `--json` and `audit session show`.

Automatic verification on every command/startup is **not added**. Existing verification reads history chains and session records; repeating that potentially unbounded historical I/O would add latency without establishing a cheap new integrity guarantee. Explicit verification remains the reliable workflow.

Interactive invalid-command/argument errors use explicit semantic spans: error red, syntax cyan, recovery/usage labels plain. Coloring does not parse human prose for keywords. ANSI-disabled rendering preserves the same readable information. Both `? case` and `case ?`, including nested paths, display help without dispatch. Invalid paths fail as help errors. This shortcut is shell-only; it does not broaden argparse command aliases or wildcard behavior. `!` requests retain their existing routing.

All output continues through existing semantic presentation/capture mechanisms. No second palette or formatting framework is added. Audit verification, capture limits, redaction, journal integrity, JSON schemas and session shutdown recording remain unchanged.
