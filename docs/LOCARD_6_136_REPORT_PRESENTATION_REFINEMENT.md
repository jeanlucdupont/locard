# Locard 6.136 — Report presentation refinement

## Scope and authority

Implemented from `20c21ca8371d5d8cc97e54af24a94bb1d2f213de` (accepted 6.135). Source version is 6.136 in `pyproject.toml`. This is a presentation change, not a new evidence or reporting store. No S1/S2/S3, investigation, source-restoration, findings-review, or publication safety rules were changed.

`recorded_view.view()` produces shared section, paragraph, card and table blocks. Audience selection and ordering happen there; `render()` emits escaped static HTML. `recorded_model.POLICIES` identifies the presentation policy; `recorded._build()` selects it using the recorded renderer version. The complete validated content remains in `projection.json`.

| Profile | Main purpose | Selection boundary |
|---|---|---|
| Executive | Objective, original S3 status, active accepted findings, uncertainty, existing recommendations | Expand observations only through displayed accepted findings. Otherwise show accurate clause counts by artifact, not an invented importance ranking. Unreviewed hypotheses and questions are counted and retained canonically. |
| Technical | Structured S3 propositions, all S1 observations/interpretations, registered relationships, decisions and provenance | Full original support appendix; nested S3 evidence is retained canonically instead of reprinted. Earlier-frontier explanation relationships stay explicitly historical. |
| Handover | Current state, original questions, proposed examinations, accepted/proposed/rejected/superseded findings and decision history | Expand support through displayed findings; separate unverified proposals, unknowns and continuation limits. No inferred plan or new authorization. |

Every profile states its presentation scope. Finishing an authorized plan does not establish whole-case completeness. No accepted findings is explicitly distinguished from absence of original observations. No summaries or recommendations are generated by a model.

## References, original text and qualifications

Application-controlled `o-N`, `r-N`, `f-N`, `p-N` and `q-N` anchors provide concise observation, relationship, finding, original-support and qualification references. Labels are deterministic for a fixed projection, not persistent cross-report identities. Findings link to supporting/contrary units; relationships link to observations; observations link to original support; decisions link to findings. References omitted from expansion get a compact identity entry explicitly pointing to the preserved canonical unit.

Original values and question wording are never clipped or rewritten. Question text uses exact equality for display deduplication, with occurrence counts; near-duplicates and unfinished text remain distinct. All original question records remain in the projection. Recorded questions carry an unverified/potentially incomplete wording notice.

Only identical qualification strings share a Q entry. Each expanded observation/relationship/finding keeps its applicable links; distinct wording is never merged. Qualifications remain visible in a non-collapsible section. Source truncation and warnings remain in material uncertainty. Provenance, original field pointers, values, lineage and EIDs are printed in technical detail and preserved canonically for all views.

Historical proposal aliases are **not** report references: the report explicitly labels them source-proposal-local and points to the canonical alias mapping. It does not silently rebind an `O1` appearing in model prose to the report's `O1`. Historical model proposals remain unverified; registered deterministic relationships are not relabeled model inference.

Coverage uses recorded counts and limitations. Technical page accounting is tabular; other profiles give compact page accounting with explicit overlap caveats. Omission identities, full disclosure ledgers, per-page detail and source-proposal mappings remain in the bundle. Omitted evidence is not described as irrelevant.

## Compatibility and security

- New renderer/policy: `recorded-html-v2`. Original projection contract remains `recorded-investigation-report-v1`.
- `recorded_view_v1.py` preserves the original 6.135 renderer. Inspection chooses the stored renderer; source revalidation rebuilds using its stored policy. Old bundles are neither rewritten nor silently rerendered using v2.
- Policy changes affect the semantic content digest, as intended. Generation metadata and HTML bytes have separate binding. Rendering does not mutate the projection. Original S3 and all non-policy source content compare equal before/after.
- CSP, escaped UTF-8 output, byte admission, guarded publication and input-mutation checks remain. No JavaScript, remote resources, file navigation or evidence-generated links.
- Only application-created `Reference` objects create anchors; source dictionaries with the same apparent keys remain inert text. All links are local fragments and must resolve before rendering succeeds.
- Print CSS, wrapping, monospaced detail cells, heading hierarchy and tables replace nested description lists. Authority is expressed in text, not color alone. No collapsed essential material.
