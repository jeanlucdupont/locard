# Locard V3: local semantic retrieval

**SEMANTIC SIMILARITY != FORENSIC EVIDENCE.**
**RAG HELPS LOCATE EVIDENCE; IT DOES NOT CREATE EVIDENCE.**

V3 (0.4.0) retains schema 3 and all V0/V1/V2 deterministic commands. No V3
migration is needed. Original evidence, IDs, parser provenance and source locations
remain authoritative. Derived indexes can be rebuilt without changing evidence.

## Installation and explicit setup

The tested semantic environment is Windows x64, Python 3.12. Install in a virtual
environment using `python -m pip install -e ".[semantic]"`. The base installation
does not import or require the semantic dependencies. Embeddings run on CPU with
four threads; MiniCPM can retain its GPU allocation. `pip check` verifies the
resolved environment, not forensic correctness.

Explicitly download the reviewed model before investigating:

```powershell
locard semantic setup data/semantic-models/bge --model bge
locard --db data/case.db semantic build --model-path data/semantic-models/bge
locard --db data/case.db semantic status
locard --db data/case.db semantic search "PowerShell downloading an executable" --model-path data/semantic-models/bge
locard --db data/case.db semantic search "persistence" --artifact registry --hostname LAB-SYNTHETIC --model-path data/semantic-models/bge
locard --db data/case.db ask "Find evidence related to persistence" --embedding-model data/semantic-models/bge --dry-run
locard --db data/case.db semantic rebuild --model-path data/semantic-models/bge
```

Setup is the only semantic operation that downloads files. It receives no case
or query text. Investigation loads local files only, disables Hub telemetry and
remote code, uses safetensors, and never falls back to cloud inference. An offline
machine can receive the complete reviewed model directory from another machine.
Missing or altered files fail clearly. Local files and the analyst account are
trusted installation boundaries; recorded hashes are integrity checks, not signatures.

BGE-small-en-v1.5 is pinned to revision
`5c38ec7c405ec4b44b94cc5a9bb96e735b38267a`. Its 384-dimensional normalized vectors
use exact FAISS CPU inner-product search. The model manifest records file hashes;
the index records package versions, token limit, model identity and representation
version. A different runtime identity requires an explicit rebuild. Bit-identical
floating-point output across different CPUs/runtime builds is not promised.

The smaller all-MiniLM-L6-v2 candidate was evaluated at revision
`1110a243fdf4706b3f48f1d95db1a4f5529b4d41`. It was faster but missed two labeled
concepts in the mixed synthetic evaluation; it is not the recommended model.

## Representations and bounds

Representations are deterministic structured text. EVTX uses mapped process,
command/script and event fields. MFT includes allocation, names and separately
labeled SI/FN observations. Prefetch includes execution observations and bounded
references. Registry includes keys and textual/numeric values with containing-key
last-write semantics. Binary Registry values, raw evidence bytes, and raw XML are
not embedded. No path is resolved against the workstation, no URL is followed,
and no script or command is executed.

Evidence IDs and acquisition paths remain in the evidence/mapping records; long
hashes and acquisition paths are excluded from embedding text. Every chunk maps
to the original evidence ID, source/subtype, representation version and character
range. Chunks are not independent evidence.

Each field is capped at 16,384 characters, a representation at 65,536 characters,
and an evidence record at 16 chunks. Timestamp/object/reference collections are
bounded. Chunk boundaries use the pinned tokenizer's measured limit (512 tokens
for BGE), including semantic labels. Builds report truncated-record counts.
The default workload cap is 100,000 vectors; `--max-vectors` can explicitly raise
it to at most 1,000,000. Hitting the cap aborts publication, preserving the previous
index. Batches contain at most 16 chunks. A 1,024-entry exact-text cache avoids
re-embedding identical representations without merging evidence or vector mappings.

## Sidecar lifecycle and integrity

The default index directory is `<database-path>.semantic-index`; `--index` can
override it for semantic commands, and `--semantic-index` for `ask`.
It contains generation directories, a SQLite vector/evidence mapping, fixed-width
float32 vectors, a manifest and an atomically replaced CURRENT pointer. Native
FAISS serialized indexes and pickle are never loaded. Search constructs bounded
in-memory exact indexes over eligible vector blocks.

Build/rebuild reads a consistent SQLite snapshot. A canonical streaming digest
includes every authoritative table and cell, including provenance and raw bytes.
Queries revalidate content within the same read snapshot used for filtering.
Counts can reject an obviously stale index early but never establish freshness.
Model/version mismatches, missing mappings and corrupted vector files fail closed.
No query downloads, builds, repairs or updates an index. There is no incremental
update command in V3.

Validation is deliberately conservative: ingestion-run changes, provenance-only
changes, or physical row ordering changes can require rebuilding. Full content
validation has a measurable cost even when vector search is fast. Concurrent
ingestion may wait for SQLite read transactions. A long build represents its
starting snapshot; later changes make it stale. Old and interrupted generations
are retained locally, not silently deleted.

## Retrieval, explanations and limitations

Exact IDs, users, paths, event IDs, process trees and timestamps stay deterministic.
Conceptual questions can supplement deterministic retrieval with semantic search.
SQL applies artifact/time/host/user/path constraints before vector ranking.
Semantic scores are cosine similarity, never confidence, probability or risk.

Hybrid retrieval expands at most five semantic hits through existing deterministic
investigation functions and retains at most 100 records. Explicit matches and
supported relationships retain priority. Semantic and weaker contextual tiers
rotate artifact classes to limit domination. Candidate/selected/omitted artifact
counts and per-record selection reasons are exposed. Numeric similarity is not
passed to MiniCPM as evidentiary weight. All relationship statuses originate in
the deterministic engine.

Search considers all eligible vectors but retains a bounded 2,000-chunk candidate
pool; truncation is reported. Duplicate evidence IDs collapse at selection time.
Whitespace-equivalent representations can be suppressed conservatively, with
suppressed IDs exposed. No evidence is deleted. This is intentionally narrower
than fuzzy clustering: differing timestamps, hosts and paths are not normalized
away. Chunk and duplicate domination can still reduce returned diversity within
the bounded candidate pool.

Hybrid hydration rejects SQLite rows exceeding 2 MiB rather than copying many
large original payloads into the model-selection process. Use deterministic
commands to inspect such records. Other documented representation and bundle
limits can omit relevant text; absence from results does not prove absence of activity.

System instructions and JSON investigator/evidence fields are separate; adversarial
artifact text remains escaped data. The model has no tools. Citations are checked
against supplied original evidence IDs, and correlation labels remain engine-owned.
These safeguards do not prove that generated prose is correct or immune to all
prompt injection. Analysts must inspect original evidence and reported omissions.

## Privacy and licensing

Indexes, embeddings, cached representations and model inputs may reveal case
information. Treat derived sidecars with the same access controls as evidence;
they are not encrypted by Locard. Do not publish them. Ignore rules exclude model
weights, indexes and staging directories, including sensitive filenames within
source-adapter directories. Review staged files and history before public release.

Locard source is Apache-2.0. See LICENSE and THIRD_PARTY_NOTICES.md. Dependencies
and models retain their own licenses; the existing AGPL dependency means a full
distribution must not be described as Apache-only.

## Validation

Ordinary tests use a synthetic embedding model and require no downloaded models
or MiniCPM. `tests/v3_evaluation.py` is an explicit integration/evaluation program
using only generated fixtures and local model directories. It compares SQL,
semantic and hybrid recall/precision at ten, artifact diversity and duplicate IDs.
Its labels identify retrieval candidates, not proof of the investigated hypothesis.
See VALIDATION.md for measured results and performance limitations.
