# EVTX numeric-array compatibility (6.70)

Locard's `forensic_assistant/ingest/evtx_arrays.py` provides a minimal,
source-controlled extension to the pinned python-evtx 0.8.1 decoder. The
substitution traversal and XML renderer are adapted from upstream Apache-2.0
code, with its copyright/license notice retained. No installed package is
modified, no process-global monkeypatch is installed, and no dependency changes
are required. `evtx_recovery.Record` uses this subclass through the existing
validated record-boundary path.

Supported numeric array substitution types are 0x84, 0x86, 0x88, 0x8A, 0x94 and 0x95.
Values are little-endian unsigned integers. Windows comparison establishes
unsigned decimal rendering or lowercase, unpadded `0x` hexadecimal rendering,
and repetition of the containing XML element for each item (one empty element for an empty array). Arrays are not
joined into a string. The supported element shape has one array substitution
as its sole content; unvalidated mixed/attribute array positions fail explicitly.
Scalar conversion and XML escaping continue to use upstream behavior.

Lengths must be nonnegative, divisible by element width, and within the mapped
buffer, chunk data, enclosing record payload and enclosing length-delimited
BinXML payload. Unsupported types still raise; malformed data is not skipped.
Existing chunk CRC, record framing, hashing, normalization, provenance and
300-second deadline behavior were unchanged by the array phases (see the supervisor phase below).

The header assessment in `evtx_recovery.py` uses the existing supported structural
checks (major 3, minor 1 or 2, magic and header sizes) together with the actual
header checksum, rather than upstream's minor-version-1-only `verify()`.
Malformed/unsupported structures remain rejected; checksum failure still produces
an explicit diagnostic and follows the existing recovery policy. Chunk/bounds
checks remain independent.

compared for array element values/order, provider and event identifiers, including

## Unsigned 16-bit array extension (0x86)

The only runtime change is the type-map entry `(2, "H", False)`: two-byte,
little-endian unsigned elements rendered in decimal by the existing decoder.
All existing length/alignment checks, record/chunk/buffer/BinXML boundaries,
ordered element expansion and empty-array behavior are reused. No header,
deadline, normalization, provenance, transaction, UI or provider code changes.

Windows comparison on NTFS Operational record 31646 proves two 0x86 arrays:
`RunsInCachedRuns`, two raw bytes, sequence `[4420]`, and
`MostPopulatedBinCountInCachedRuns`, two raw bytes, sequence `[70]`.
Locard and Windows emit identical field values. The record's 0x88 field is now
validated from complete rendered XML rather than expecting a later failure.

endian/order/extreme-value tests, malformed and odd-length rejection, empty

## Supervised EVTX stall timeout (6.70)

Normal interactive and scripted EVTX ingestion now use
`forensic_assistant/ingest/evtx_worker.py`. The previous in-process generator's
300-second lifetime check could count normalization/database work and could not
interrupt a hang inside XML rendering. That cooperative deadline is removed
from the low-level framing decoder. The supervisor controls an independent
worker, and can terminate it even when `record.xml()` never returns.

Defaults per file: 300 seconds without observed forward parser position, plus
an independent 21,600-second (six-hour) emergency ceiling from worker launch.
`--parser-timeout` selects EVTX stall seconds (1..3600); it retains its previous
wall-clock semantics for other artifacts. `ingest-evtx` and `ingest-all` also
accept `--evtx-hard-timeout` (1..86400 seconds). Interactive guided ingestion
uses the same defaults and implementation without prompts or retry menus.

Progress consists of a strictly increasing physical source position reported
when moving to the next aligned chunk, reaching a record with verified framing,
or advancing beyond a processed record. Existing recovery may advance to the
next chunk after a bad chunk; this is actual movement, not a successful-record
claim. Equal/backward positions, worker liveness, spinner refreshes and error
counts do not reset the timer. Position reports are coalesced to at most ten per
second into a bounded append-only binary IPC stream; incomplete entries are
ignored until complete. There is no cosmetic heartbeat or broad IPC framework.

The supervisor reuses the actual-PID containment handshake, Windows kill-on-close
job/Unix process-group cleanup, and parser-worker 2 GiB memory guard. XML/error
frames go to a private temporary spool (8 GiB maximum, 64 MiB maximum frame),
not the evidence database. The parent supervises until worker exit, confirms
cleanup, then replays complete frames through the existing normalization,
disk-backed staging, before/after source hashing and publication transactions.
This means parent normalization/database processing is outside the worker timer.
Spooling delays normalization until parsing stops but does not change file-level
compact progress output or add diagnostic panels.

A stall or hard-ceiling termination replays complete frames already flushed and
adds an explicit terminal parsing error, so published records are marked partial.
An incomplete final frame is not imported. Existing recovery diagnostic counts
and resume offsets are reconstructed during replay. Worker/protocol/resource
failures also produce incomplete outcomes; unconfirmed process cleanup raises
`CleanupError` rather than returning safely to the interactive prompt. Temporary
spools are removed on completion/failure/cancellation. Cancellation preserves
the previous publication semantics: unpublished current-file staging is discarded,
while prior committed files remain intact and interruption is recorded.

Timeout errors distinguish `EVTX parser stalled: no forensic progress for ...`
from `EVTX parser emergency hard ceiling reached: ...`. No decoder, normalization,
source identity, schema, hashing or publication semantics were changed.
CertificateServices nested BinXML and the four nonstandard event-trace files
remain unresolved.

Focused validation: 104 tests passed, including mocked-time healthy runs beyond
300 seconds, no-progress/liveness stalls, progress resumption and hard-ceiling
termination; real blocked-XML worker/descendant cleanup; cancellation; partial
publication; byte-equivalent normalized events; framing, arrays, identifiers,

No full regression suite, commit or push is part of this implementation phase.
